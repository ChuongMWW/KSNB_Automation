QUY TRÌNH TÍNH THƯỞNG KỸ THUẬT VIÊN SỬA CHỮA CE

Cơ chế tự động xác định và tính thưởng KTV dựa trên Code tính thưởng, Code dịch vụ, Linh kiện thực tế và đơn giá được duyệt.

1

Mục tiêu quy trình

Xây dựng cơ chế tự động xác định và tính thưởng cho Kỹ thuật viên (KTV) dựa trên:

🎯 Các yếu tố đầu vào:
  • Code tính thưởng (Master Key).
  • Code dịch vụ thực hiện trên Vận đơn.
  • Linh kiện thực tế sử dụng (SKU).
  • Đơn giá thưởng hiện hành được KSNB khai báo theo phê duyệt của Giám đốc.
  • Mapping chuẩn giữa: Code tính thưởng ↔ Code dịch vụ ↔ Code linh kiện.
⭐ Giá trị mang lại:
  • Loại bỏ hoàn toàn việc tính thưởng thủ công.
  • Đảm bảo tính đúng Code, đúng linh kiện, đúng đơn giá.
  • Cung cấp khả năng đối soát minh bạch và lưu vết lịch sử (Audit Trail).
2

Phạm vi áp dụng & Hệ thống liên quan

Áp dụng cho các Vận đơn sửa chữa có phát sinh linh kiện và dịch vụ và có thực hiện tính thưởng cho KTV.

Hệ thống Vai trò trong quy trình
TMS Quản lý vận đơn Thợ, ghi nhận linh kiện/dịch vụ thực tế và trạng thái hoàn tất vận đơn (Trigger tính thưởng).
3

Nguyên tắc tính thưởng cốt lõi

🔑 3.1. Code tính thưởng là khóa tính thưởng (Master Key)
Hệ thống không sử dụng "Nhóm linh kiện" làm khóa tính thưởng. Code tính thưởng được tạo riêng biệt và là khóa tham chiếu duy nhất để xác định đơn giá thưởng áp dụng.

3.2. Phân tách trách nhiệm các bộ phận:

Bộ phận Trách nhiệm cụ thể
QLDV Gửi yêu cầu tạo Code tính thưởng và đề xuất Mapping: Code tính thưởng ↔ Code linh kiện ↔ Code Dịch vụ.
QC Tạo Code tính thưởng trên hệ thống và cập nhật mô tả Code.
Giám đốc Phê duyệt đơn giá thưởng áp dụng cho từng Code.
KSNB Khai báo đơn giá thưởng, thời gian hiệu lực và trạng thái theo phê duyệt của Giám đốc.
Hệ thống Tự động xác định linh kiện/dịch vụ sử dụng và tính thưởng ngay khi Vận đơn hoàn tất.
4

Quy trình 1 – Tạo Code tính thưởng

Bước Ai làm (Actor) Làm gì (Action) Location Hệ thống làm gì (System Logic) Trạng thái & KPIs
1 Quản lý dịch vụ Gửi yêu cầu tạo Code tính thưởng mới, nêu rõ dịch vụ/linh kiện áp dụng BCNB Tiếp nhận yêu cầu Có thể cấu hình
2 QC Kiểm tra yêu cầu và tạo Code tính thưởng Masterdata Sinh Code tính thưởng duy nhất Xây mới nếu chưa có
3 QC Cập nhật thông tin mô tả Code Masterdata Lưu thông tin Code Xây mới / Điều chỉnh
4 KSNB Tiếp nhận Code đã được QC tạo BCNB Hiển thị Code cần khai báo đơn giá Xây mới / Điều chỉnh
5 Giám đốc Phê duyệt đơn giá thưởng áp dụng BCNB Ghi nhận căn cứ phê duyệt nếu có workflow Workflow phê duyệt
6 KSNB Khai báo đơn giá thưởng, thời gian hiệu lực và trạng thái TMS Lưu đơn giá gắn với Code Tỷ lệ khai báo đúng
7 Hệ thống Kích hoạt Code/đơn giá khi đủ điều kiện TMS Cho phép Code được sử dụng để tính thưởng Active tính thưởng
📦 Kết quả đầu ra của mỗi Code tính thưởng:
Mỗi Code tính thưởng sau khi tạo phải có tối thiểu: Code tính thưởng, Mô tả, Đơn giá thưởng, Người tạo, Người khai báo đơn giá, Căn cứ/phê duyệt đơn giá.

Quy trình 2 – Mapping Code tính thưởng

5.1. Mục đích: Xác định Code tính thưởng nào được áp dụng cho từng tổ hợp Code dịch vụ/linh kiện.

5.2. Cấu trúc Master Mapping (Bảng đề xuất: MAP_CODE_THUONG_DICHVU_LINHKIEN):

Trường dữ liệu Mô tả chi tiết
Code tính thưởng (*) Tham chiếu Master Code tính thưởng
Code linh kiện (SKU) (*) SKU linh kiện được áp dụng
Code dịch vụ (*) Code dịch vụ sửa chữa tương ứng
Trạng thái Active / Inactive
Người tạo Mapping Quản lý dịch vụ

Ví dụ dữ liệu Mapping mẫu:

STT MÃ SP TÍNH THƯỞNG MÃ LINH KIỆN _ DỊCH VỤ
1 Dịch vụ thay led_Tivi < 50inch Thanh led_Tivi LED 4K 43P635_TCL_B0101-000584
2 Dịch vụ sửa chữa không thay linh kiện_Tivi Dịch vụ sửa chữa cơ bản
3 Dịch vụ thay led_Tivi ≥ 50inch < 65inch Đèn led_TIVI LED SAMSUNG UA43T6000_ĐP

5.3. Luồng Mapping:

Bước Ai làm Làm gì Làm ở đâu System Logic
1 Quản lý dịch vụ Xác định Code dịch vụ và SKU cần áp dụng thưởng QT ngoài Nhập thông tin Mapping
2 Quản lý dịch vụ Khai báo Code thưởng ↔ Code dịch vụ ↔ SKU TMS Kiểm tra dữ liệu bắt buộc và chống trùng Mapping
3 Hệ thống Kiểm tra Mapping TMS Tìm theo tổ hợp Code dịch vụ + SKU
4 Hệ thống Xác định Code tính thưởng TMS Nếu Mapping tồn tại ➔ lấy Code tính thưởng
5 Hệ thống Kiểm tra trạng thái Code TMS Chỉ sử dụng Code đang ở trạng thái Active
6 Hệ thống Lấy đơn giá hiện hành TMS Xác định đơn giá theo thời gian hiệu lực

Quy trình 3 – Tự động tính thưởng KTV

6.1. Trigger kích hoạt: Khi Vận đơn chuyển trạng thái = Hoàn tất, hệ thống tự động kích hoạt tiến trình tính thưởng.

6.2. Luồng xử lý chi tiết:

Bước Actor Hành động (Action) Location System Logic Ghi chú quan trọng
1 Hệ thống Nhận trạng thái Vận đơn = Hoàn tất TMS Trigger quy trình tính thưởng Sự kiện kích hoạt
2 Hệ thống Lấy toàn bộ linh kiện đã sử dụng TMS Xác định các SKU thực tế đã sử dụng trên JC/Vận đơn Lấy đúng linh kiện xuất
3 Hệ thống Lấy Code dịch vụ TMS Xác định Code dịch vụ của Vận đơn Không phải code dịch vụ mapping với linh kiện
4 Hệ thống Tìm Mapping TMS Tìm Mapping theo Code dịch vụ + Linh kiện sử dụng Khớp dữ liệu Master
5 Hệ thống Xác định Code tính thưởng TMS Lấy Code tính thưởng từ kết quả Mapping Khóa tham chiếu
6 Hệ thống Lấy đơn giá TMS Lấy đơn giá hiện hành của Code tính thưởng Theo thời điểm hoàn tất
7 Hệ thống Tính tổng thưởng TMS Cộng đơn giá thưởng của toàn bộ linh kiện hợp lệ Tổng thưởng trước giảm trừ
8 Hệ thống Kiểm tra số lượng linh kiện TMS Nếu số lượng linh kiện ≥ 2 ➔ áp dụng hệ số 80% Giảm trừ 20%
9 Hệ thống Lưu giao dịch thưởng KTV TMS Ghi nhận kết quả tính thưởng và dữ liệu nguồn Lưu vết đối soát
7

Công thức tính thưởng & Hệ số điều chỉnh

7.1. Tổng thưởng trước điều chỉnh:

Tổng thưởng bằng tổng đơn giá của tất cả các Code tính thưởng hợp lệ:

TongThuong = Σ DonGia(CodeThuong_i)

7.2. Điều chỉnh theo số lượng linh kiện (Hệ số Qty):

Số lượng linh kiện sử dụng Hệ số thưởng áp dụng Công thức tính tiền thưởng
1 linh kiện 100% (Không giảm) ThuongKTV = Σ DonGia(CodeThuong_i)
≥ 2 linh kiện 80% (Giảm 20%) ThuongKTV = Σ DonGia(CodeThuong_i) × 80%

9

Kết quả đầu ra & Chuỗi truy xuất ngược (Audit Trail)

Kết quả cuối cùng của quy trình là một giao dịch thưởng KTV có thể truy xuất ngược đầy đủ 100% theo chuỗi:

KTV ➔ Jobcard / Vận đơn ➔ Code dịch vụ ➔ SKU Linh kiện ➔ Bảng Mapping ➔ Code tính thưởng ➔ Đơn giá ➔ Hệ số Qty ➔ Tiền thưởng KTV
✅ Điểm chuẩn hóa cốt lõi:
Code tính thưởng là Master Key, còn Code dịch vụ + SKU là điều kiện để hệ thống tìm ra Code đó thông qua bảng Mapping. Chuẩn hóa này loại bỏ hoàn toàn rủi ro khi dùng “Nhóm linh kiện” làm khóa tính thưởng.
